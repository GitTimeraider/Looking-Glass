How to connect your OPNsense

Looking Glass combines two channels: syslog (OPNsense pushes logs, real time) and the REST API (Looking Glass pulls system state, CrowdSec, Q-Feeds, IDS and Unbound data). Use both for the best coverage.

  1. API key — in the OPNsense web UI go to System › Access › Users, create a user (e.g. lookingglass), give it the privileges it needs (simplest: GUI - All pages; stricter: only the Diagnostics, Reporting, Firmware, Gateways, Unbound, CrowdSec, Q-Feeds and Intrusion Detection pages — any endpoint that returns 403 shows up in the polling table above). In the user's API keys section click +; a file with key= and secret= downloads. Enter the URL (e.g. https://192.168.1.1), key and secret under Settings › OPNsense and click Test connection, then Save.
  2. Remote syslog — System › Settings › Logging, tab Remote (called Logging / targets on older versions), click +: Enabled ✓, Transport UDP(4) (or TCP(4)), Applications: leave empty to send everything (recommended) or pick filter (filterlog), unbound, nginx, crowdsec, suricata, sshd, audit, openvpn, dhcpd/kea…; Levels: everything from info up; Hostname: the IP of the Docker host running Looking Glass; Port: the host port mapped to Looking Glass's syslog port (514 in the example compose file, container port {{ syslog_port }}); rfc5424 ✓. Save & Apply.
  3. Firewall logging — default block rules are logged out of the box (Firewall › Settings › Advanced › Logging). Tick Log on the pass rules / port forwards you care about (WAN inbound!) so allowed traffic is visible too. Without syslog Looking Glass pulls the live firewall log via the API instead (FIREWALL_LOG_PULL=auto).
  4. Unbound DNS — enable the Unbound DNS statistics in Reporting › Settings (off by default) so Looking Glass can pull per-client queries via the API, and/or Services › Unbound DNS › Advanced › Log Queries (+ Log Replies) for full query logs over syslog.
  5. nginx plugin — error logs reach syslog automatically. For access logs open Services › Nginx › Configuration, tab Other › SYSLOG Targets, add a target with Host = Docker host, Port = 514, then select it under HTTP(S) › HTTP Server › SYSLOG targets (Access Log Format main or main_ext). nginx then sends access logs straight to Looking Glass.
  6. CrowdSec (os-crowdsec) — nothing extra: alerts and decisions are pulled via the API; its log lines arrive through syslog.
  7. Suricata IDS/IPS — Services › Intrusion Detection › Administration: tick Enable syslog alerts (and optionally Enable eve syslog output). Alerts are also pulled from the API.
  8. Zenarmor — Zenarmor › Settings › Streaming Data. Works on every edition including free Home: Stream Reporting Data to External Elasticsearch with URI http://<docker-host>:9200 and Elasticsearch version 8.11.3 (Looking Glass acts as the Elasticsearch node). Paid editions can alternatively stream to syslog (Docker host, port 514). Don't pick the install wizard's Remote Elasticsearch Database - that replaces local storage. See Zenarmor docs.
  9. Q-Feeds (os-q-feeds-connector) — events only exist for logged firewall block rules that use the Q-Feeds aliases (e.g. LAN: block to alias, WAN: block from alias, Log ✓). Looking Glass pulls them from Security › Q-Feeds Connect › Events via the API. Domain feeds go into Unbound's blocklist.
  10. GeoIP (optional) — create a free MaxMind account, download GeoLite2-City.mmdb (or Country) into the mounted /data volume, restart. Countries then appear in dashboards and reports.
  11. AI analyst — under Settings › AI analyst enter your API key. Defaults use Anthropic's OpenAI-compatible endpoint (https://api.anthropic.com/v1/, model claude-opus-5-5); any other OpenAI-compatible endpoint (OpenAI, OpenRouter, LiteLLM, Ollama…) works by changing base URL and model.
