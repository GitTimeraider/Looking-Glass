Full setup guide – every step with explanations

Looking Glass combines two channels: syslog (OPNsense pushes logs, real time) and the REST API (Looking Glass pulls system state, CrowdSec, Q-Feeds, Suricata and Unbound data). Use both for the best coverage.

  1. API key — in the OPNsense web UI go to System › Access › Users, create a user (e.g. lookingglass), give it the privileges it needs (simplest: GUI - All pages; stricter: only the Diagnostics, Reporting, Firmware, Gateways, Unbound, CrowdSec, Q-Feeds and Intrusion Detection pages — any endpoint that returns 403 shows up in the polling table above). In the user's API keys section click +; a file with key= and secret= downloads. Enter the URL (e.g. https://192.168.1.1), key and secret under Settings › OPNsense and click Test connection, then Save.
  2. Remote syslog — System › Settings › Logging, tab Remote (called Logging / targets on older versions), click +: Enabled ✓, Transport UDP(4) (or TCP(4)), Applications: leave empty (recommended). Only then are the general System logs (kernel, opnsense …), sshd logins and API-key failures sent; none of these has an entry in the list. If you pick instead: filter (filterlog), resolver (unbound), audit (audit), lighttpd, openvpn, ipsec (charon), wireguard, suricata, kea/dnsmasq/dhcpd, configd, kernel. Levels: everything from info up (Unbound query lines are info); Hostname: the IP of the Docker host running Looking Glass; Port: the host port mapped to Looking Glass's syslog port (514 in the example compose file, container port {{ syslog_port }}); rfc5424 ✓. Save & Apply.
  3. Firewall logging — default block rules are logged out of the box (Firewall › Settings › Advanced › Logging). Tick Log on the pass rules / port forwards you care about (WAN inbound!) so allowed traffic is visible too. Without syslog Looking Glass pulls the live firewall log via the API instead (FIREWALL_LOG_PULL=auto).
  4. Unbound DNS — enable Unbound DNS statistics in Reporting › Settings (off by default); Looking Glass pulls every query with client, answer and blocklist from it. Do not also enable Log Queries / Log Replies in Services › Unbound DNS › Advanced: that duplicates every query and slows Unbound down.
  5. nginx plugin — OPNsense remote syslog only forwards nginx's global error log, never the access logs (they are files on the firewall). Looking Glass therefore reads access, error and stream logs through the nginx API (Settings › OPNsense › Pull nginx access / error logs, on by default; the API user needs the nginx pages). A nginx SYSLOG target is not needed; only if you want access logs in real time instead of once a minute, add one (Host = Docker host, Port = the syslog port, tag nginx) and then switch the pull off, otherwise every request is counted twice.
  6. VPN — WireGuard writes no connection logs at all, so peers, handshakes and traffic come from the API (Pull VPN status, on by default), as do OpenVPN sessions and IPsec tunnels. Logins and connects of OpenVPN / IPsec also arrive via syslog (openvpn, ipsec (charon)).
  7. CrowdSec (os-crowdsec) — nothing extra: alerts and decisions are pulled via the API (CrowdSec writes no syslog on OPNsense).
  8. Suricata IDS/IPS — nothing extra: alerts are pulled from the API (Pull Suricata IDS alerts). Do not also tick Enable syslog alerts in Intrusion Detection, that would count every alert twice.
  9. Zenarmor — Zenarmor › Settings › Streaming Data. Works on every edition including free Home: Stream Reporting Data to External Elasticsearch with URI http://<docker-host>:9200 and Elasticsearch version 8.11.3 (Looking Glass acts as the Elasticsearch node). Paid editions can alternatively stream to syslog (Docker host, port 514). Don't pick the install wizard's Remote Elasticsearch Database - that replaces local storage. See Zenarmor docs.
  10. Q-Feeds (os-q-feeds-connector) — events only exist for logged firewall block rules that use the Q-Feeds aliases (e.g. LAN: block to alias, WAN: block from alias, Log ✓). Looking Glass pulls them from Security › Q-Feeds Connect › Events via the API. Domain feeds go into Unbound's blocklist.
  11. GeoIP (optional) — create a free MaxMind account, download GeoLite2-City.mmdb (or Country) into the mounted /data volume, restart. Countries then appear in dashboards and reports.
  12. AI analyst — under Settings › AI analyst enter your API key. Defaults use Anthropic's OpenAI-compatible endpoint (https://api.anthropic.com/v1/, model claude-opus-5-5); any other OpenAI-compatible endpoint (OpenAI, OpenRouter, LiteLLM, Ollama…) works by changing base URL and model.
